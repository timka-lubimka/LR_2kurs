## Сборка и запуск

Нужны `g++` с поддержкой C++17 и установленный Go. Если установлен `make`, из корня проекта запустите:

```sh
make cpp
make go
```

В Windows (PowerShell) без `make`:

```powershell
mkdir bin -Force
g++ -std=c++17 -O2 cpp/*.cpp LR-1/cpp/stack.cpp LR-1/cpp/array.cpp LR-1/cpp/queue.cpp LR-1/cpp/doubly_list.cpp -o bin/lr2-cpp.exe
cd go
go build -o ../bin/lr2-go.exe .
cd ..
```

Пример запуска в PowerShell:

```powershell
'5 5 2 C D +' | .\bin\lr2-cpp.exe baseball
'5 5 2 C D +' | .\bin\lr2-go.exe baseball
.\bin\lr2-cpp.exe set_commands --file set.data --query 'SETADD 10'
```

В Linux/macOS запускайте `./bin/lr2-cpp baseball` и `./bin/lr2-go baseball`.

## Формат стандартного ввода

Каждая задача (кроме 2) получает вход через stdin. Приведены работающие примеры.

**baseball**: `N`, затем N операций `5 2 C D +` (каждая операция допускается на отдельной строке). `5\n5 2 C D +` → `30`.

**set_commands**: `--file data.txt --query "SETADD value"` (или `SETDEL value`, `SET_AT value`). Файл содержит значения, разделённые пробелами/переводами строк. Операции сохраняют изменённое множество; проверка не меняет файл. Сложность **ожидаемая O(1)** на операцию, амортизированно, при качественной хеш-функции; худший случай O(n).

**set_partition**: `N target`, затем N **различных натуральных** чисел. Пример `6 15\n4 10 5 1 3 7` → две группы суммы 15. Если нельзя — `Impossible`. Перебор с отсечениями, экспоненциальный в худшем случае.

**subsets**: `N`, затем N различных токенов; выводит все 2^N подмножеств (не непрерывные подмассивы: именно так показано в примере регламента). `3\nx y z`. Ограничение N≤20, поскольку результат экспоненциален.

**right_view**: `N`, затем N чисел для **вставки в бинарное дерево поиска** (дубликаты игнорируются). Вывод правого вида сверху вниз. Пример: `7\n8 3 10 1 6 14 4` → `8 10 14 4` (последний видимый уровень — 4; для другого примера выход будет другим). В регламенте изображение дерева, без текстового списка вставки; формат ввода оговорён здесь.

**hash_task**: первая строка/токен — десятичный ключ; далее необязательный N и N дополнительных ключей. Пример `523456795` → `Fold: 523+456+795 = 1774`, затем два блока статистики. Каждая десятичная строка разбивается слева направо на тройки цифр, их суммы используются как ключи. Показатели `time_us` варьируются между запусками и не должны сравниваться без многократного повторения.

**lru_task**: `capacity Q`, затем Q операций `SET key value` / `GET key`, по одной или нескольким на строке. Выводится значение для каждого GET, либо -1. При переполнении удаляется давно не использованный ключ. Новая вставка и обновление считаются обращениями.

## Связь с ЛР1 и сложность

- Задача 1 — `Stack` и `pushStack/popStack/getStackTop` из `LR-1/cpp/stack.*`, `Stack.push/pop` из `go/stack.go` (копия ЛР1).
- Задачи 3–4 — `Array` из ЛР1, плюс пользовательское множество для проверки уникальности.
- Задача 5 — `TreeNode` из ЛР1 (C++), очередь `Queue` ЛР1 для BFS; дерево **BST**, поэтому вставка не использует `insertInTree`, которое в ЛР1 строит *полное* дерево. В Go BST-узел определён дополнительно, очередь из ЛР1.
- Задачи 2 и 6 — новая хеш-таблица с открытой адресацией (в ЛР1 такой структуры не было), надстроенная поверх основ ЛР1.
- Задача 7 — `DoubleList` и `DoubleNode` из ЛР1 с индексом по ключам. C++ использует указатели на узлы, Go — копию двусвязного списка ЛР1.

**Оценки:** стековые операции O(1); генерация подмножеств O(n·2^n); построение BST O(nh) и BFS O(n); LRU O(1) ожидаемое на SET/GET; хеш-операции O(1) ожидаемое амортизированно и O(n) в худшем случае.

## Методы разрешения коллизий (6.1)

- **Линейное пробирование:** при занятой ячейке исследуются соседние `(h+i) mod m`. Плюсы: проста, хорошая локальность памяти. Минус: первичная кластеризация.
- **Двойное хеширование:** `(h1+i·h2) mod m`. Плюсы: обычно меньше кластеризация. Минусы: дополнительная стоимость хеширования, необходимость правильно выбирать вместимость и шаг.

Практический эксперимент: запустить `hash_task` с сотнями/тысячами входных ключей; выводит число коллизий, проб, уникальных ключей и время. Сравнивать операции при одинаковых данных и повторять прогон. Число проб включает вставку и контрольный поиск.
